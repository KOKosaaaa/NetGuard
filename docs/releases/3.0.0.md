### v3.0.0 (2026-10-04) — WB Stream + adaptive bypass + glass interface

This release brings together the transport, routing and interface changes since
the last public release, v2.0.0.

**WB Stream profiles and automatic recovery.** Create conference transport
profiles from the managed-server wizard, import WB room links and resume setup
in the background. A completed deployment task alone does not mark a room ready:
live room and publisher state are checked. Transport changes address stalled
transfers, reconnects, owner-session recovery and relay cleanup. Available
bandwidth depends on the conference service and network; parallel transport does
not guarantee 10 MB/s.

**Connection state and server selection.** Connected status requires a confirmed
exchange through the tunnel. Server selection considers service responses
together with latency, supports cancellation and releases the search indicator
when selection ends. Automatic switching remains conservative to avoid
unnecessary interruption of active sessions. The home screen follows the actual
active server after a switch.

**Adaptive routing and bypass diagnostics.** AUTO compares direct and VPN paths
as sites are encountered, with a seven-day cache and network context. Apps can
be forced through the VPN. Supported TLS record strategies are tested separately;
probe outcomes and actual application traffic are displayed separately in
diagnostics, with copy/save actions. A successful probe alone is not proof that
an application used the bypass. **A direct route exposes your normal public IP**;
choose Global proxy when all traffic should use the VPN. HTTP/3, ECH-hidden names
and unrecognized traffic retain the core's routing rules.

**Speed testing.** Measurements use the active tunnel's authenticated SOCKS
bridge, verified TLS, bounded payloads, cancellation and alternative measurement
services. A partial or unacknowledged transfer is not reported as a completed
result. Measurement-service failures are separate from VPN availability.

**Glass interface with preserved themes.** Refreshed navigation icons, panels,
typography and connection map; connection state changes the application's accent.
The home screen adapts to the viewport without scrolling. Repeatedly selecting
Settings preserves its position. All six themes remain, including fsociety
terminal styling; the launcher icon can follow the theme.

**Sixteen languages.** Application-owned screens, dialogs, onboarding,
notifications and diagnostics use localized resources. Service brands, protocol
names and user-created server names are preserved. Third-party web login pages
remain controlled by their provider.

**Wi-Fi auto-connect.** Network callbacks and delayed checks follow the current
physical Wi-Fi association. An identity hidden by Android is treated as
untrusted after bounded retries, without claiming an Evil Twin attack. Turning
the setting off or losing the association cancels stale start attempts.

**Server agent 0.5.13 / revision 14.** Existing WB agents qualify for an update
containing the audited fixes. Authenticated binary uploads receive a bounded
four-minute reading deadline; normal API requests retain their shorter limit.
The application has matching upload timeouts, displays server error details and
confirms a new process before reporting update success. Executables are checked
by SHA-256 and a smoke test before replacement, with a backup and serialized
installation. Both amd64 and arm64 installers remain embedded in the APK.

**Release hardening.** Recovery ownership prevents an old restart from modifying
a replacement tunnel. Relay creation/stop is synchronized. Telemost/VK signaling
verifies TLS certificates and hostnames. SSH setup requires confirmation of a new
server's fingerprint and rejects a changed key; initial agent pairing is pinned
to the public key obtained over SSH. Backup format 3 keeps same-named
subscriptions separate while retaining older import support.

**Updated build (2026-10-05): SSH server setup.** SSH and agent management use the
running application's VPN proxy, including WB Stream, because the application's
own traffic is excluded from Android's TUN. SSH handshakes have bounded deadlines,
visible attempt numbers and cancellation that closes the underlying sockets.
Proxy transport keeps destination DNS inside the VPN. Fingerprint confirmation
and pinned agent pairing remain required. Background provisioning no longer
delays the successfully added server screen. This replaces the APK in the existing
v3.0.0 release; no separate release is introduced.

### Installation

Download **NetGuard-v3.0.0.apk** below. Requires **Android 8.0+ / ARM64**.
Install over the previous version: package ID and signing certificate are
preserved, including development versions 2.0.34 and 3.0.1. No uninstall is required.

Very old agents can still reject their first slow upload at the former
30-second limit. If this occurs, bootstrap the current agent over SSH first;
increasing the phone's timeout cannot change an already running old server.
New installations and successfully updated agents use the corrected deadline.

the accompanying checksum file.
