### v2.0.0 (2026-09-19) — Automatic site routing + connection stability

This release brings together the connection, subscription and routing changes since the last public release, v1.3.11.

**Automatic per-site routing.** The new AUTO mode compares whether a website responds directly or through the current VPN. The first request immediately uses the saved route, or the VPN when there is no saved result; independent HEAD probes run in the background. Results are cached for seven days and refreshed with network/server context. Established connections retain their route, and a newly measured winner applies to later sessions.

The comparison measures reachability and response latency, not download bandwidth or every authenticated page. Probe requests do not copy the user's URL path, cookies, authorization headers or request body. HTTP/3, ECH-hidden names and unrecognized traffic keep the core's routing rules without a separate per-site comparison. **A direct route exposes your normal public IP to the destination**; select Global proxy if all traffic should use the VPN.

**Conservative service failover.** Telegram, YouTube, X, Discord, ChatGPT and Reddit participate in service-health checks. A single unavailable service no longer triggers a tunnel-wide switch. Health-based failover requires all selected targets (at least two) to fail in three or more rounds spanning at least 90 seconds, with no meaningful received traffic; switches have a five-minute minimum interval. Site-route comparisons do not restart the VPN. Real network/server failures can still interrupt active sessions.

**Happ subscription compatibility.** Expanded link-wrapper, Base64 and JSON import; XHTTP/REALITY configuration support; bounded retries and subscription downloads through an active VPN. This improves compatibility with supported Happ-style subscriptions without assuming every provider-specific format or access rule is interchangeable.

**Actual active server on the home screen.** The server label, map and speed test follow the tunnel's active profile after automatic failover. Cancelled or outdated map lookups cannot restore the previously selected server's marker.

**Tunnel and transport changes.** Xray runs through libXray JNI in a dedicated Android service process; the TUN bridge uses hev JNI. TCP/UDP forwarding, traffic counters and Telemost recovery were updated, including relay cleanup and reliable striped transport. The bundled server agent is now 0.4.1.

**Encrypted storage and compact packaging.** SQLCipher encrypts the profile database with migration from the existing plaintext database. The site-route cache is encrypted as well. The APK retains both amd64 and arm64 server installers, compressed internally; users install one normal APK without extracting an archive.
